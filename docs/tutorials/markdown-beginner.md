# Markdown 零基础入门：从第一行文字到一篇清晰的算法题解

第一次打开题解编辑器，看见 `##`、`**` 和三个反引号，是不是不知道该怎么下手？

Markdown 是一种用少量符号组织文章的写法。你输入的仍然是普通文字，只需要在合适的位置加上符号，就能得到标题、列表、加粗和代码块。不会编程也可以学习 Markdown；会写程序的人，则可以用它把代码和解释整理成容易阅读的题解。

这篇文章只讲 Markdown。数学公式的专门写法属于 LaTeX，可以在掌握文章排版后再学。

## 1. 先用一分钟写出第一段内容

把下面的内容复制到题解编辑器的**正文**中，再切换到“预览”：

```markdown
## 解题思路

我们先计算前缀和，避免每次查询都重新遍历数组。

**关键观察：两个前缀的差，就是一个区间的和。**

## 算法步骤

1. 从左到右计算前缀和。
2. 对每个查询，输出两个前缀的差。
```

你会看到两个小节标题、一段普通文字、一句加粗的重点，以及一个编号列表。

记住三个习惯，就能开始写了：

- 标题符号后面留一个空格，例如 `## 解题思路`。
- 不同段落之间空一行。
- 写完一小段就看一下预览，不必等全文写完再检查。

注意：上面的代码框只是用来展示“应该输入什么”。复制内容时，不要额外把包裹示例的三个反引号也放在整篇正文外面，否则整篇文章会变成代码块。

## 2. 标题：给文章分出层次

Markdown 用 `#` 表示标题。井号越多，标题层级越低。

```markdown
# 一级标题

## 二级标题

### 三级标题
```

在我们的题解页面，最上方已经有单独的“题解标题”输入框，因此正文通常从二级标题开始：

```markdown
## 解题思路

## 算法步骤

## 复杂度分析

## 参考代码
```

如果某个小节还需要细分，再使用三级标题，例如 `### 为什么前缀和是正确的`。

不要为了把整段话变大，就把每句话都写成标题。标题的作用是告诉读者“接下来讲什么”。

## 3. 段落与换行：不要把全文挤成一块

两个段落之间空一行：

```markdown
直接计算每个区间的和，需要反复访问相同的元素。

我们先保存每个前缀的和，就能复用之前的计算结果。
```

Markdown 编辑器对“只按一次回车”的处理可能不同。我们当前的题解编辑器会保留普通换行；为了让文章复制到其他网站后也清楚，分段时仍建议空一行。

长代码的换行应放在代码块里，不要依靠手工添加空格来排版正文。

## 4. 加粗：突出真正重要的结论

在文字两边各加两个英文星号：

```markdown
**数组下标从 1 开始，prefix[0] 初始化为 0。**
```

效果：

**数组下标从 1 开始，prefix[0] 初始化为 0。**

需要较轻的强调时，也可以使用斜体：

```markdown
*这里说明一个容易忽略的边界情况。*
```

一段话里突出一两个重点通常就够了。整段都加粗，会让读者找不到真正关键的地方。

## 5. 列表：写步骤和边界情况

有先后顺序的算法步骤，用有序列表：

```markdown
1. 读取数组。
2. 计算前缀和。
3. 读取每个查询并输出结果。
```

没有先后顺序的注意事项，用无序列表：

```markdown
- 注意查询区间的左右端点都包含在内。
- 注意结果是否超出 int 的范围。
- 注意数组第 0 个位置的初始化。
```

数字后的点、列表前的减号，都使用英文符号，并在后面留一个空格。

## 6. 行内代码：解释变量、函数和短表达式

一句话里的代码，用一对反引号包起来：

```markdown
用 `prefix[i]` 表示前 i 个数的和，查询结果为 `prefix[r] - prefix[l - 1]`。
```

效果：

用 `prefix[i]` 表示前 i 个数的和，查询结果为 `prefix[r] - prefix[l - 1]`。

反引号是这个符号：`` ` ``。它不是英文单引号 `'`，也不是中文引号 `‘’`。

变量名、函数名、短代码表达式适合用行内代码；比较长的程序应该使用下一节的代码块。

## 7. 代码块：正确展示完整程序

在代码前后各放一行三个反引号，并在第一行写上语言名称：

````markdown
```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "Hello, world!" << '\n';
    return 0;
}
```
````

效果：

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "Hello, world!" << '\n';
    return 0;
}
```

常用语言标识如下：

| 编程语言 | 第一行写法 |
| --- | --- |
| C++ | 三个反引号后写 `cpp` |
| C | 三个反引号后写 `c` |
| Python | 三个反引号后写 `python` |
| Java | 三个反引号后写 `java` |
| JavaScript | 三个反引号后写 `javascript` |
| 不需要高亮的文本 | 三个反引号后写 `text` |

语言标识用于帮助编辑器着色，不会运行代码，也不会自动把错误的代码改正确。

在我们的编辑器里，可以先选择代码语言，再点击“代码块”。如果已经选中了一段正文，点击“代码块”会把选中的内容包进去。

最常见的错误是忘记最后一行的三个反引号。结果是后面的“复杂度分析”等文字也被当成代码。遇到这种情况，先检查代码块有没有正确结束。

## 8. 链接、引用和简单表格

### 插入参考链接

```markdown
参考资料：[GitHub Markdown 文档](https://docs.github.com/zh/get-started/writing-on-github)
```

写法是 `[显示文字](网址)`。使用英文方括号和英文圆括号，不要写成中文标点。

引用别人的资料、思路或代码时，应说明来源，并遵守原作者的使用要求。

### 写一段引用

```markdown
> 前缀和适合处理数组不变、区间求和查询较多的情况。
```

效果：

> 前缀和适合处理数组不变、区间求和查询较多的情况。

### 用表格比较两种做法

```markdown
| 做法 | 单次查询时间 |
| --- | --- |
| 逐个元素累加 | 与区间长度有关 |
| 预处理前缀和 | 常数时间 |
```

表头下面的 `| --- | --- |` 不能省略。不要为了对齐表格而输入大量空格，预览会负责排版。

## 9. 一篇可复制的题解模板

下面是一个适合初学者的结构。复制后，把说明文字替换成自己的分析；只填写自己实际使用和理解的方法。

````markdown
## 解题思路

这道题需要我们求出什么？

直接做法为什么不够好？关键观察是什么？为什么新的方法正确？

## 算法步骤

1. 说明初始化。
2. 说明主要处理过程。
3. 说明如何得到答案。

## 复杂度分析

- 时间复杂度：说明输入规模和主要循环的执行次数。
- 空间复杂度：说明额外使用了哪些数组或数据结构。

## 参考代码

```cpp
// 在这里放入你的实现，并为关键步骤添加必要的注释。
```

## 边界情况

- 最小规模输入。
- 容易越界或溢出的情况。
````

一篇好的题解应当让读者理解“为什么”，而不只是看到一份程序。先解释关键思路，再给代码，通常更容易读懂。

## 10. 在题解编辑器里怎么操作

1. 从题目页进入“查看 / 提交题解”，通过该题后点击“编写题解”。
2. 填写标题，再编写正文；不会记符号时使用工具栏或“插入题解模板”。
3. 桌面可以用“对照”同时看源文和效果；手机可以切换“编辑”和“预览”。
4. 观察草稿保存状态。草稿保存在当前浏览器，换设备不会自动同步，清理浏览器数据也可能使它消失。
5. 长文建议点击“下载草稿”，另存一份。
6. 检查无误后点击“提交审核”。保存草稿不等于提交；审核通过后才公开，并按系统规则奖励 10 金币。

我们的编辑器不会执行正文中的 HTML。图片语法目前显示为链接，不会自动加载外部图片。不要照搬其他编辑器特有的按钮、插件或排版语法，实际效果以本站预览为准。

## 11. 排版出错时，先检查这五件事

- **标题还是普通文字：** `##` 后面是否有空格？是否被包在代码块里？
- **加粗没有效果：** 两边是否都是两个英文星号？有没有漏掉一边？
- **全文变成代码：** 是否在整篇文章外套了三个反引号，或者某个代码块没有结束？
- **列表没有分开：** 每一项是否单独一行？减号或 `1.` 后面是否有空格？
- **链接无法打开：** 括号是否使用英文符号？网址是否完整？

如果暂时只记得标题、列表、加粗和代码块，也完全可以写出清晰的第一篇题解。先把思路说明白，再逐步完善排版。
