# 反例猎人社区界面实现记录

## Overview

本记录仅覆盖新增社区题目、题目讨论、作者编辑表单，以及个人菜单向下展开的行为。采用继承现有界面的 Operate 模式：保留蓝白 Semantic UI、原有导航和按钮语言，以阅读题意、检查错误程序、提交反例、讨论边界情况为主线。

实现依据为 `web/template/syzoj/hunt.php`、`adventure.php`、`css/hunt.css`、`css/adventure.css`、`css/desktop.css`、`header.php`、`js/account-menu.js`；请求状态由 `web/hunt.php` 提供。本文是功能范围内的记录，不扩展为全站设计规范。

## Colors

主蓝用于主要操作、链接、选中导航和键盘焦点；正文深色与辅助灰分别承担内容和元信息。白色面板通过浅边框与页面底色区分，错误程序使用深底浅字代码区。

反馈沿用浅蓝底与深蓝字；错误状态使用浅红底（#fff0f1）与红字（#982f3b），命中反馈使用绿字（#176940），并附有文字结果，避免只依赖颜色。

## Typography

桌面沿用系统无衬线栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`，正文（14px / 1.6）。移动端继承原站字体设置。

页面标题（32px，窄屏 28px）、面板标题（24px / 1.4）、辅助说明（13px）建立层级。题意与评论保留换行，行高（1.8），允许长词断行；普通面板段落最大宽度（72ch）。

源码字段使用 `ui-monospace, SFMono-Regular, Consolas, monospace`，制表符宽度为 4。展示代码字号（14px，窄屏 12px），行高（1.8）；源码输入关闭拼写检查，允许纵向调整高度。

## Layout

详情按题意与错误程序、反例提交、最近挑战结果（有记录时）、本题讨论依次排列。管理操作位于对应程序下方，评论删除位于对应评论旁。页面标题附近提供社区题目、我的题目、我要出题入口。

桌面主容器宽度为 `min(1280px, calc(100% - 64px))`。面板使用统一内边距与面板间距；作者表单最大宽度（860px），标题、题意、语言、错误程序、参考程序、输入校验程序纵向排列，三个程序均为完整源码字段。

小于 1000px 时，内容外侧留白（16px），面板内边距（24px 20px），标题操作区改为纵向，既有挑战双栏布局变为单栏。列表元信息换行，按钮最小高度（44px）。640px 及以下，评论时间单独成行，局部操作继续允许换行。

展示代码区域自身滚动且最大高度（480px）；外层 `pre` 使用 `white-space: pre`，内层 `code` 继承原站的 `pre-wrap`，实际窄屏显示会保留换行并自动折行。长标题和普通文字断行，避免把长内容扩散为页面级横向溢出。源码编辑字段保持纵向堆叠。

## Elevation & Depth

面板以边框和底色分层；个人菜单沿用 Semantic UI 的轻阴影（0 1px 3px，黑色 8%）与下侧 4px 圆角，依靠边框、白底和位置表达浮层。新增界面不引入装饰性动效或独立视觉框架。

## Shapes

输入框、菜单、面板分别使用 frontmatter 中对应圆角。作者字段使用细边框（1px，#b8c6d8）、白底和内边距（10px 12px）。代码展示区圆角为 8px。

## Components

- **发布表单**：每个字段有明确 label；题意、校验规则通过 `aria-describedby` 关联帮助。提示包含源码大小、同语言约束、标准输入输出以及 VALID / INVALID 协议。发布或保存为主操作，取消为链接。
- **反例提交**：明确标注“反例输入”，说明可提交空输入、大小及频率限制。登录前显示登录并挑战入口；下架后显示暂停挑战与新评论的说明。
- **结果反馈**：错误用 `role="alert"`，验证结果用 `role="status"`；输入输出放入原生 details / summary。等待较长时提示稍后刷新与联系管理员，提供“刷新验证结果”链接；旧版本结果有文字说明。
- **讨论**：绑定当前题目，保留纯文本和代码换行，输出经过转义。未登录、暂无评论及分页有对应文案和入口；删除按钮包含评论作者的可访问名称。
- **个人菜单**：固定宽度（196px），纵向条目，位于触发器下方且右对齐。条目最小高度（42px）、内边距（10px 16px）；退出行用分隔线区分。悬停使用浅蓝底（#edf3ff）和主蓝文字。
- **菜单定位与键盘**：触发器可聚焦，带“个人菜单”名称与 `aria-haspopup`；悬停和 `focus-within` 展开，内部链接保留原生键盘顺序。小于 1000px 时菜单固定定位，脚本在指针进入、聚焦、点击、导航滚动、窗口滚动和缩放时更新位置，使其脱离横向导航的裁切范围；高度受剩余视口限制，可纵向滚动。
- **焦点**：继承全站可见焦点轮廓（2px 主蓝，偏移 3px）和跳至主内容链接。现有导航在窄屏仍可横向滚动。

## Do's and Don'ts

- 保持题意 → 错误程序 → 反例输入 → 本题讨论的阅读顺序，以及作者完整源码字段的纵向标签结构。
- 保留原有个人菜单项目、导航路径和横向滚动；不要为此次局部扩展改造全站导航或另建组件体系。
- 不把源码显示区的内部滚动改成页面级溢出；窄屏检查标题、帮助文字、按钮和菜单条目是否仍可阅读及触达。
- 不把界面审阅视为原生沙箱或生产部署认证。本次 finish review 结论为 ship，范围为本地界面；证据为本地验收附件目录中 detail/menu 的 1440、1200、390、320px 截图，以及 editor 的 1440、390px 截图。
- 截图和源码审阅不等于完整交互无障碍审计：计算对比度、全部键盘转换、读屏表现及所有未截图状态未在该审阅中逐一验证；C++ / Python 原生沙箱执行、生产基础设施和部署不在其认证范围。
